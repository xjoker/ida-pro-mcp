# v1.5 容器化部署可行性评估

> 评估时间：2026-05-14
> 评估分支：`feat/v1.5-container-ida-eval`
> 基线版本：1.4.0.dev1（多机部署预览）
> 评估方式：advisor agent（architect tier / Opus）深度分析 + 主线索调研

---

## TL;DR

**结论：技术上可行，商业上受 IDA license 类型约束**。

- ✅ Linux 容器内运行 IDA（idalib headless）**技术可行**（debian/ubuntu glibc base + IDA 9.x Linux 安装目录）
- ✅ Coordinator 立即可容器化（纯 Python，零 IDA 依赖）
- ⚠️ Worker 容器化需要用户自带 IDA license + 二进制（不可公开发布镜像）
- ❌ **node-locked 个人 license 与容器漂移冲突**，多 worker 必须 named-user / floating license
- ❌ Alpine（musl）不兼容，必须 glibc base image
- ⚠️ 现有代码需要 4 处小改造（advertise host、依赖拆分、健康端点、信号处理）

**推荐路径**：v1.5 提供 docker-compose 模板 + 文档，K8s 留到 v1.6+。

## 1. IDA Pro License 矩阵

| License 类型 | 容器可行 | 多 Worker 扩展 | 关键约束 |
|---|---|---|---|
| **Computer (node-locked)** | ❌ 不推荐 | ❌ 不可 | 绑 MAC + 主机指纹。容器 MAC 随网络栈漂移，IDA 启动会触发 re-activation 或拒绝运行。单 license 仅一台机器并发 |
| **Named User (cloud)** | ✅ 可行 | ⚠️ 受限 | 需出站 HTTPS 到 `*.hex-rays.com`。同一 named user 同时仅 1 个 active session，多 worker 需多个 seat |
| **Floating (license server)** | ✅ **推荐** | ✅ 可 | 配置 `HEXRAYS_LICENSE_FILE` 指向内网 license server。worker 数 = seat 数；启动借出、退出归还 |
| **Site / Enterprise** | ✅ 推荐 | ✅ 可 | 同 Floating，企业内网部署 |
| **IDA Free** | ❌ 不支持 | n/a | 无插件 API，本项目已声明不兼容 |

**关键事实**：
- 仓库内**没有任何 license / hardware-fingerprint 检测代码**（仅 `installer.py:403-409` 探测 idafree license 文件，与 worker 运行时无关）
- License 验证完全由 `import idapro` 在 `idapro.open_database()` 触发（黑盒）
- **容器化可行性 = 用户的 license 类型**

## 2. Linux 容器内运行 IDA：技术约束

### Base Image
- ✅ `debian:bookworm-slim`（glibc 2.36）
- ✅ `ubuntu:22.04`（glibc 2.35）
- ✅ `ubuntu:20.04`（glibc 2.31，IDA 9.x 最低要求）
- ❌ `alpine:*`（musl 不兼容 idalib）
- ❌ `python:*-alpine`（同上）

### Python 版本对齐
IDA 9.0 自带 Python 3.12 binding（`idapro.so` 链接到特定 libpython）。容器 Python 必须与 IDA 安装目录里的 Python **完全对齐**，否则 `import idapro` 段错误。
- 用 `idapyswitch` 或显式 `python3.12-minimal`
- 我们项目要求 Python ≥3.11，但 IDA 9.x 通常配 3.12

### IDA 安装目录
- 体积 2–4 GB
- 含 GUI Qt 库（不会 load，可剥离瘦身但风险高）
- 含 `procs/*.idp` 多架构插件
- 实测推荐：**不剥离**，避免兼容性问题

### Headless 运行
- idalib 不需要 X11 / Xvfb / Qt 启动（与 Wine 跑 GUI IDA 不同）
- 启动入口：`import idapro; idapro.open_database(path)`
- 进程纯 CPU/IO 密集，无图形栈依赖

### 文件系统
- IDB 文件需 worker 可读写：volume mount / NFS / 共享卷
- license 文件位置：`HEXRAYS_LICENSE_FILE` 或 `~/.idapro/`，需挂载

## 3. Dockerfile 设计选项

| 选项 | 描述 | 优 | 劣 |
|---|---|---|---|
| **A** 用户提供 base image | `FROM your-registry/ida:9.0` 之上叠加 Python 包 | 镜像层清晰、IDA 升级独立、CI 友好 | 用户需先自建 IDA base 镜像 |
| **B** Build-time COPY | `COPY ./ida-install/ /opt/ida/` | 单 Dockerfile、可在 CI build matrix | 把 IDA 写进镜像层、泄漏风险高、必须私有 registry |
| **C** Runtime volume mount | `-v /host/ida:/opt/ida:ro` | 镜像不含商业二进制、可公开发布、升级 IDA 不重 build | 编排复杂（K8s 需 hostPath/CSI）、冷启动慢 |

### 推荐：**A（生产）+ C（开发）双轨**
- **生产用 A**：企业 registry 维护 `ida-base:9.x` 镜像（手动 build 一次），上层 `ida-pro-mcp-worker` 镜像只 COPY 本仓库 src。可发布到公司内部 registry
- **开发用 C**：本地开发挂载本机已装 IDA，零 build 开销

### Coordinator 最简 Dockerfile（可公开发布）

```dockerfile
FROM python:3.12-slim-bookworm
WORKDIR /app
COPY pyproject.toml ./
COPY src/ ./src/
RUN pip install --no-cache-dir .[coordinator]   # 拆 extras 后只装 redis + tomli-w
ENV PYTHONUNBUFFERED=1
EXPOSE 9000
ENTRYPOINT ["ida-mcp-coordinator", "--host", "0.0.0.0", "--port", "9000"]
CMD ["--registry-url", "redis://redis:6379/0"]
HEALTHCHECK --interval=10s --timeout=3s \
  CMD python -c "import http.client,sys; \
    c=http.client.HTTPConnection('127.0.0.1',9000); \
    c.request('GET','/coordinator/health'); \
    sys.exit(0 if c.getresponse().status<300 else 1)"
```

资源需求：单核 <100MB RSS，1 vCPU + 256 MB 充裕。

### Worker Dockerfile 模板（A 方案，用户填）

```dockerfile
# 用户准备 ida-base:9.x 镜像（一次性 build，含 IDA 安装目录 + Python 3.12）
ARG IDA_BASE=your-registry.example.com/ida-base:9.0

FROM ${IDA_BASE}
WORKDIR /app
COPY pyproject.toml ./
COPY src/ ./src/
RUN pip install --no-cache-dir .[worker]
ENV PYTHONUNBUFFERED=1
# advertise-host 必须用 K8s downward API 或 docker network alias 注入
ENV WORKER_ADVERTISE_HOST=""
EXPOSE 13337
ENTRYPOINT ["idalib-mcp", "--host", "0.0.0.0", "--port", "13337"]
CMD ["--registry-url", "redis://redis:6379/0"]
```

## 4. 现有代码改造清单

### 必需（容器内根本跑不起来）

| # | 文件 | 改造 | 原因 |
|---|---|---|---|
| 1 | `src/ida_pro_mcp/idalib_server.py:412-419` | 新增 `--advertise-host`（默认回退 `--host`），优先读 env `WORKER_ADVERTISE_HOST` | 容器内 `--host 0.0.0.0` 会被注册成 "0.0.0.0"，coordinator 无法连接。K8s 用 downward API 注入 pod IP |
| 2 | `pyproject.toml:24-28` | `idapro>=0.0.7` 移到 `[project.optional-dependencies] worker` extras | Coordinator 不需要 idapro，纯 Linux CI 环境装 idapro PyPI 包会失败 |

### 优化（不改也能跑但容器体验差）

| # | 文件 | 改造 | 原因 |
|---|---|---|---|
| 3 | `src/ida_pro_mcp/coordinator.py:133-192` | `/coordinator/health` 在 `worker_count==0` 时返回 503 | Docker/K8s healthcheck 才能正确判断 unhealthy + 摘流 |
| 4 | `src/ida_pro_mcp/coordinator.py:502-513` | 注册 `SIGTERM` handler → `server.stop()`，主线程改 `threading.Event().wait()` | 当前用 `input()` 等待退出，容器 stdin 关闭即退；docker stop 时被 SIGKILL |
| 5 | 全局 logging 配置 | logging 改 `StreamHandler(sys.stdout)` + entrypoint 加 `ENV PYTHONUNBUFFERED=1` | 容器日志收集器友好 |
| 6 | 文档 | 说明 "1 容器 = 1 worker = 固定端口"；现有 port auto-increment 是单机 GUI 多实例设计 | 端口 auto-increment 在容器内是反模式 |

## 5. jadx-mcp 风格的实例管理（v1.4 已大部分实现）

**用户提问背景**：希望像 `jadx-mcp` 那样动态管理多个分析实例（`add_jadx_instance` / `list_jadx_instances` / `set_default_jadx_instance` / `create_transfer_token`）。

### jadx-mcp 模式 vs 我们 v1.4 已有的能力

| 能力 | jadx-mcp | ida-pro-mcp v1.4 |
|---|---|---|
| **动态注册 instance** | `add_jadx_instance(url)` MCP 工具 | ⚠️ 仅自动注册（worker 启动时 register 到 Redis） |
| **列举 instance** | `list_jadx_instances()` | ✅ Coordinator `/coordinator/health` + RegistryRouter |
| **健康检查** | `health_check_jadx_instances()` | ✅ Registry TTL + heartbeat |
| **选择默认 instance** | `set_default_jadx_instance(id)` | ⚠️ 仅自动路由（IDB 亲和 + 负载） |
| **per-request 选择** | tool 参数指定 instance | ✅ `tools/call.arguments.database` 已支持 |
| **大数据传输令牌** | `create_transfer_token` HTTP 旁路 | ❌ 未实现 |
| **客户端管理 UI/API** | MCP 工具 | ❌ 暂未暴露为 MCP 工具 |

### v1.5 应该补的 4 个 MCP 工具（jadx-mcp 风格）

让 MCP 客户端能在会话中动态管理 worker pool，无需重启 coordinator。

```python
@tool
def add_ida_instance(
    url: Annotated[str, "Worker endpoint URL, e.g. http://host:13337"],
    capabilities: Annotated[list[str] | None, "Optional capabilities list"] = None,
    auto_register: bool = True,
) -> dict:
    """Register an external IDA worker instance to the coordinator.
    
    Worker 通常自动注册到 Redis，但允许 MCP 客户端手动添加
    （如内网穿透场景、未配置 Redis 的临时 worker）。
    """

@tool
def remove_ida_instance(worker_id: str) -> dict:
    """Deregister a worker (does not stop the worker process)."""

@tool
def list_ida_instances() -> list[dict]:
    """List all registered workers + their loaded IDB + score + health."""

@tool
def set_default_ida_instance(worker_id: str | None) -> dict:
    """Set the default routing target for subsequent tools/call without explicit 'database' arg.
    Pass None to clear (resume auto IDB-affinity routing)."""
```

### 实现成本估算
- 完全复用现有 `Registry` + `RegistryRouter`
- 新建 `src/ida_pro_mcp/distributed/api_instances.py` 暴露 MCP 工具（~200 行）
- 已有 `select_best(prefer_idb)` 扩展为 `select_best(prefer_idb, prefer_worker)` 支持 default instance
- 测试 ~10 个用例
- **预估工作量：1 个 wave，1 个 implementer agent，~3 小时**

## 6. 风险 / 卡点清单

### 用户必须自己解决（仓库不可代劳）
- 持有合法 IDA Pro license（推荐 floating / named-user，禁用 node-locked）
- 自建 IDA base image（A 方案）或挂载 IDA 目录（C 方案）
- 私有 registry 存放含 IDA 二进制的镜像
- IDB 文件存储：NFS / S3FUSE / 共享 volume（worker 之间需要看到同一 IDB 才能命中 affinity 路由）

### 代码可解决（v1.5 范围）
- 第 4 节列出的 6 项改造

### 建议放弃的场景
- ❌ K8s 上跑 node-locked license worker（license server 失效率 + pod 漂移 = 频繁挂）
- ❌ Alpine base image
- ❌ IDA Free 容器化（无插件 API）
- ❌ 公开发布含 IDA 的 worker 镜像到 Docker Hub（license 违规）

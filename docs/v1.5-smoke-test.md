# v1.5 容器化小验证 (Smoke Test)

本文档描述如何在**无需 IDA Linux 二进制**的情况下，验证 v1.4/v1.5 多机部署架构在容器内的工作流程。

---

## 验证目标

- ✅ Coordinator 镜像 build + 启动正常
- ✅ Mock Worker 容器化注册到 Redis Registry
- ✅ Coordinator 通过 Registry 发现 mock workers
- ✅ Coordinator forward MCP 请求到 mock worker，收到响应
- ✅ IDB 亲和性路由命中正确的 worker
- ✅ Worker 退出时 deregister 干净

**特别注意**：本套件**不依赖真实 IDA**，使用 `mock_worker.py` 模拟 idalib 注册行为。等你下载 IDA Linux 后，把 `Dockerfile.worker.template` 填充后即可替换 mock worker。

---

## 前置条件

- Docker Desktop 或 Docker Engine（已验证 v29+）
- Docker Compose v2（已验证 v5+）
- 端口 6379 / 9000 / 13337 可用

## 一键验证

```bash
bash tests/smoke/verify.sh
```

脚本会自动 build、启动、探测 5 个验收点、最后 teardown。预期看到 5 个 `[ ok ]`。

## 分步验证

### 步骤 1：启动栈

```bash
bash tests/smoke/verify.sh up
```

预期：

- `idamcp-smoke-redis` 起来（Redis 7-alpine，60 MB 内存）
- `idamcp-smoke-coordinator` build 成功并启动（基于 python:3.12-slim-bookworm）
- `idamcp-smoke-mock-worker-1` build 成功并启动
- `idamcp-smoke-mock-worker-2` build 成功并启动
- Coordinator 健康检查通过

```bash
# 查看运行状态
docker compose -f tests/smoke/docker-compose.smoke.yml ps
```

### 步骤 2：探测

```bash
bash tests/smoke/verify.sh probe
```

5 个探测点：

#### Probe 1: 健康端点
```bash
curl http://localhost:9000/coordinator/health | jq
```
预期：JSON 含 `mode: "registry"` + `workers: [...]`（2 个 mock workers）+ `registry_status: "ok"`

#### Probe 2: Worker 注册
预期：Registry 报告 ≥2 个 workers，含 worker_id（UUID4 hex）、host (`mock-worker-1` / `mock-worker-2`)、port (13337)

#### Probe 3: tools/list forwarding
```bash
curl -X POST http://localhost:9000/mcp \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```
预期：返回 mock worker 提供的工具列表（`mock_decompile`、`mock_disasm`）。说明 forwarder + RegistryRouter 工作正常。

#### Probe 4: IDB 亲和路由
```bash
curl -X POST http://localhost:9000/mcp \
  -H 'Content-Type: application/json' \
  -d '{
    "jsonrpc":"2.0","id":2,"method":"tools/call",
    "params":{
      "name":"mock_decompile",
      "arguments":{"database":"/demo/sample.idb","ea":"0x401000"}
    }
  }'
```
预期：响应文本包含 `mock-worker-1`（因为它是模拟加载 `/demo/sample.idb` 的实例）。
说明 RegistryRouter `select_best(prefer_idb=...)` 命中 IDB 亲和性。

#### Probe 5: 资源占用
预期：
- Redis ~10 MB RSS
- Coordinator ~50 MB RSS
- 每个 mock worker ~30 MB RSS

### 步骤 3：teardown

```bash
bash tests/smoke/verify.sh down
```

## 故障排查

### Coordinator build 失败
```
ERROR: failed to solve: process "/bin/sh -c pip install ..."
```
通常是网络/PyPI 镜像问题。在 Dockerfile.coordinator 第一行 RUN 之前加：
```dockerfile
RUN pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple
```

### Coordinator 启动后立即退出
```
docker compose logs coordinator
```
看是否：
- `Connection refused` → Redis 未就绪（compose 的 `depends_on: service_healthy` 应已避免，重试 `up`）
- `Address already in use` → 主机 9000 端口被占用

### Mock worker 注册失败
```
Failed to register worker XYZ: ...
```
通常是 Redis 连接问题。验证：
```bash
docker exec -it idamcp-smoke-redis redis-cli ping
```
应返回 `PONG`。

### IDB 亲和路由未命中
检查 mock-worker-1 是否真的上报了 `loaded_idb`：
```bash
docker exec idamcp-smoke-redis redis-cli SMEMBERS idamcp:idb:$(echo -n '/demo/sample.idb' | sha256sum | cut -d' ' -f1)
```
应至少返回 1 个 worker_id。

## 切换到真 IDA Linux Worker

当你下载 IDA Pro Linux 版本后：

### 选项 A：build 私有 ida-base 镜像（推荐生产）

1. 写一个 `Dockerfile.ida-base`（不进仓库，仅本地/私有 registry）：
   ```dockerfile
   FROM ubuntu:22.04
   RUN apt-get update && apt-get install -y \
       python3.12 python3.12-venv python3-pip \
       libxcb1 libgomp1 libxkbcommon0 \
       && rm -rf /var/lib/apt/lists/*
   COPY ./ida-install/ /opt/ida/
   ENV PATH=/opt/ida:$PATH
   ENV PYTHONPATH=/opt/ida/python:/opt/ida
   ENV IDADIR=/opt/ida
   ```
2. Build：
   ```bash
   docker build -t your-registry.example.com/ida-base:9.0 \
       -f Dockerfile.ida-base .
   ```
3. 修改 `tests/smoke/Dockerfile.worker.template` 顶部的 `ARG IDA_BASE=...` 默认值
4. Build worker：
   ```bash
   docker build -t ida-mcp-worker:1.5.0 \
       --build-arg IDA_BASE=your-registry.example.com/ida-base:9.0 \
       -f tests/smoke/Dockerfile.worker.template .
   ```
5. 替换 docker-compose.smoke.yml 中的 `mock-worker-1` / `mock-worker-2`，把镜像换成 `ida-mcp-worker:1.5.0`，volume mount 你的 IDB 文件

### 选项 C：runtime volume mount（推荐开发）

直接在 compose 里 mount 本机 IDA 安装目录，跑 ubuntu:22.04 base：

```yaml
worker-1:
  image: ubuntu:22.04
  volumes:
    - /Applications/IDA Pro 9.0/ida.app/Contents/MacOS:/opt/ida:ro  # macOS path
    - ./your-idbs:/data:rw
  environment:
    PATH: /opt/ida:/usr/bin
    PYTHONPATH: /opt/ida/python:/opt/ida
  command: >
    bash -c "apt-get update && apt-get install -y python3.12 python3-pip
             && pip install -e /app[worker]
             && idalib-mcp --host 0.0.0.0 --port 13337
                  --registry-url redis://redis:6379/0
                  --advertise-host $$HOSTNAME"
```

⚠️ macOS 上的 IDA 二进制是 **darwin** ABI，无法在 Linux 容器内运行。容器必须用 IDA **Linux 版本**。

## 已知限制（v1.5-alpha）

1. **`--advertise-host` 参数尚未实现** — 见 [v1.5 评估文档](v1.5-container-evaluation.md) 第 4 节改造清单 #1。当前 mock_worker.py 已支持，但真 `idalib_server.py` 还要等代码改造 PR
2. **Coordinator `/health` 在 0 worker 时仍返 200** — 改造清单 #3
3. **Coordinator SIGTERM handler 未实现** — 改造清单 #4，目前 `docker stop` 时 10s 后被 SIGKILL
4. **pyproject.toml 未拆 extras** — 当前 Coordinator Dockerfile 用 hack 绕过 idapro 依赖，等 #2 改造完成后可清理

这些限制不影响 smoke test 验证 v1.4 多机架构本身。完整 production-ready 化在 v1.5.0-alpha1 实施。
